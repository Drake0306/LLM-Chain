# LLM-Chain v1.2 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship multimodal LoRA — fine-tune a vision-language model (Qwen2-VL) on local image+text JSONL data using the existing train-and-go flow.

**Architecture:** Add Qwen2-VL entries to the registry, a new `jsonl_chat_vision` dataset format, and two new trainers (`HfVlmTrainer` for CUDA, `MlxVlmTrainer` for Apple Silicon). The vision encoder stays frozen; LoRA targets only the LM linears. UI gates the model picker by modality so text datasets hide VLMs and vice versa.

**Tech Stack:**
- HF transformers + peft for the CUDA path (`Qwen/Qwen2-VL-2B-Instruct`, `Qwen/Qwen2-VL-7B-Instruct`).
- `mlx-vlm` for the Apple Silicon path (subprocess wrapper, mirrors how MLX text training works today).
- Pillow for image loading; standard JSONL for the dataset.

**Why this scope:** v1.0 + v1.1 covered text-only LoRA end-to-end plus the post-train loops (GGUF, Hub push). The next user pain point is "fine-tune on my screenshots / receipts / document photos." Multimodal LoRA on a VLM is the smallest cut that delivers that. Pretraining-from-scratch (the other v1.2 candidate) is dropped — hobby-scale pretraining produces worse models than the smallest open base, and validation on a Mac is brutal.

**Out of scope for this batch:**
- Multi-image turns (single image per user turn for v1.2; multi-image is v1.3).
- Vision encoder LoRA — we LoRA the LM head only; vision encoder frozen.
- Audio modality and image-output models.
- CPU multimodal — vision encoders are heavy, no useful experience there.
- VLM families other than Qwen2-VL (LLaVA, Idefics, MiniCPM-V, etc. are v1.3).

**Mode:** autonomous, like v1.1. Each task is its own commit, push after pytest + vitest + cargo check pass. No GitHub Release tag without explicit go-ahead.

---

## Order

1. **Registry + dataset format types** — smallest, no new training paths. Adds Qwen2-VL entries and `DatasetFormat.JSONL_CHAT_VISION`, plus a `?modalities=text,image` filter on `/api/models`.
2. **JSONL chat-vision loader** — parses OpenAI-style content arrays, resolves image paths relative to the JSONL, rejects missing-image rows with a clear error.
3. **VLM trainers (CUDA + MLX) + dispatch** — `HfVlmTrainer`, `MlxVlmTrainer`, and `make_trainer("cuda_vlm" / "mlx_vlm", …)`.
4. **UI: dataset format option + modality gate + smoke** — DatasetPicker exposes the new format, ModelPicker filters by modality, end-to-end smoke on Qwen2-VL-2B with a 4-image fixture.

Each commits independently. If anything snowballs in scope, stop and surface it.

## Task 2: JSONL chat-vision loader

**Why:** The new format reuses the chat shape but allows content arrays so a turn can mix text and images. The loader must (a) parse content arrays, (b) resolve image paths relative to the JSONL parent dir, (c) reject rows that point at missing files so a typo surfaces immediately instead of mid-training.

**Files:**
- Modify: `sidecar/llm_chain_sidecar/datasets/loader.py` — add `_load_jsonl_chat_vision(path: Path) -> list[dict]`. Each returned row:
  ```python
  {
    "messages": [
      {"role": "user", "content": [
        {"type": "image", "path": "/abs/path/img.png"},
        {"type": "text", "text": "What does this say?"},
      ]},
      {"role": "assistant", "content": [{"type": "text", "text": "It says hello."}]},
    ]
  }
  ```
  Image paths in the input may be relative; absolutize against the JSONL's parent dir.
- Modify: `sidecar/llm_chain_sidecar/datasets/types.py` — `DatasetFormat.JSONL_CHAT_VISION` added in Task 1.
- Create: `sidecar/tests/datasets/test_loader_jsonl_vision.py`:
  - happy path: row with one image + text
  - relative path resolution: `./img/1.png` resolved against fixture dir
  - absolute path passthrough
  - missing image raises with a clear "image not found at <path>" message
  - assistant turn with plain string content is normalized to a single-text content array (back-compat)
- Create: `sidecar/tests/datasets/fixtures/vision/sample.jsonl` and two ~50×50 PNG files (`a.png`, `b.png`) checked in.

**Tests to write first (TDD):** All five test cases above; run them red before implementing the loader branch.

**Acceptance:** All 5 vision loader tests pass. Existing JSONL chat loader tests still pass. Total sidecar pytest: 96+ passed.

**Commit message:** `feat(datasets): JSONL chat-with-images loader for multimodal training`

## Task 3: VLM trainers (CUDA + MLX) + dispatch

**Why:** The training step. Qwen2-VL needs a `processor` (image + text) instead of a plain tokenizer; peft LoRA targets only the LM linears (`q_proj`, `k_proj`, `v_proj`, `o_proj` on the language_model submodule) — the vision encoder stays frozen. CUDA uses HF Trainer + peft like the text path. MLX subprocesses `mlx-vlm`'s built-in `lora` command and parses its stdout for loss/step events.

**Files:**
- Create: `sidecar/llm_chain_sidecar/trainers/hf_vlm.py` — `HfVlmTrainer`:
  - Loads `AutoProcessor.from_pretrained(model_id)` and `AutoModelForVision2Seq.from_pretrained(model_id, torch_dtype=torch.bfloat16)`.
  - Builds peft `LoraConfig` with `target_modules=["q_proj","k_proj","v_proj","o_proj"]` and `modules_to_save=["lm_head"]`. Vision tower frozen by default in peft when target_modules doesn't match.
  - Same TrainerCallback queue + thread bridge as `HfCudaTrainer`.
- Create: `sidecar/llm_chain_sidecar/trainers/mlx_vlm.py` — `MlxVlmTrainer`:
  - Subprocesses `python -m mlx_vlm.lora --model <id> --train --data <jsonl> --iters …`.
  - Parses stdout lines like `Iter 1: ... Train loss 2.345 ...` for STEP events; emits DONE on clean exit, ERROR on non-zero.
- Modify: `sidecar/llm_chain_sidecar/trainers/__init__.py` — add to `make_trainer`:
  ```python
  if backend == "cuda_vlm":
      return HfVlmTrainer(*args, **kwargs)
  if backend == "mlx_vlm":
      if sys.platform != "darwin":
          raise RuntimeError("MLX VLM backend requires macOS")
      return MlxVlmTrainer(*args, **kwargs)
  ```
- Modify: `sidecar/pyproject.toml` —
  - Add `Pillow>=10.0` to base `dependencies`.
  - Add `mlx-vlm>=0.1` to the `mlx` extra alongside `mlx>=0.15`, `mlx-lm>=0.18`.
- Create: `sidecar/tests/trainers/test_hf_vlm.py` — mirrors `test_hf_cuda.py`:
  - `test_hf_vlm_yields_start_then_steps_then_done` (mocks `_run_training_loop`).
  - `test_hf_vlm_translates_download_events`.
  - `test_make_trainer_cuda_vlm_returns_hf_vlm_trainer`.
- Create: `sidecar/tests/trainers/test_mlx_vlm.py` — mirrors `test_mlx.py` shape; mocks subprocess and verifies stdout parsing.

**Tests to write first (TDD):** Test files first with the event-shape assertions, then implement the trainers to satisfy them. Patch out the heavy imports (`AutoProcessor`, `AutoModelForVision2Seq`) per the existing `test_hf_cuda` pattern.

**Acceptance:** Unit tests pass for both trainers. `make_trainer` returns the right class for both new backend strings. Total sidecar pytest: 102+ passed.

**Commit message:** `feat(trainers): VLM training paths for CUDA (HF) and Apple Silicon (mlx-vlm)`

## Open questions (defaults that don't block start)

1. **Acceptance fixture size** — 4 images. Plenty for a sanity check; less than that and HF batches funny. Default: 4.
2. **Qwen2-VL-7B in registry** — ~8 GB quantized, just barely fits 16 GB unified Macs in QLoRA. Default: include both 2B and 7B; the existing VRAM tier filter will hide 7B from underspec'd hosts.
3. **Dataset preview thumbnails** — DatasetPicker could render the first 2–3 images. Default: counts only; thumbnails are a polish item for v1.3 because Tauri local-file-protocol handling is fiddly.

If these need to flip, surface and we adjust before Task 4.
