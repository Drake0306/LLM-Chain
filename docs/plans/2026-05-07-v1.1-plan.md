# LLM-Chain v1.1 Implementation Plan

**Goal:** Land the v1.1 features that can be implemented and validated on the maintainer's Apple Silicon Mac. Hardware-bound items (AMD ROCm, Intel XPU, NVIDIA-Unsloth speedup validation) stay parked until the right host is available; telemetry stays deferred until there's a user base worth measuring.

**Why this scope:** v1.0 shipped the foundation. The biggest unaddressed user pain points are (a) "I trained an adapter, now what?" — answered by GGUF export and HF Hub push — (b) "this Mac doesn't have an Nvidia GPU and I can't even open the app on a non-trainable host" — answered by CPU fallback — and (c) "I want to fine-tune Llama / Gemma / DeepSeek and I know they're restricted" — answered by the restricted-license toggle. None of these need new training hardware to validate end-to-end; all four can be smoked on this MacBook.

**Out of scope for this batch:**
- AMD ROCm backend (needs an AMD/Linux box).
- Intel XPU + IPEX-LLM backend (needs an Intel Arc box).
- Unsloth-on-NVIDIA speedup validation (needs an NVIDIA box; we can write the wiring but can't smoke-test the speedup here).
- Opt-in anonymous telemetry (v1.0 has no users; nothing to measure yet — revisit when we have an alpha cohort).

**Mode:** autonomous, like the polish batch — each task is its own commit, push after local pytest + vitest + cargo check pass. No new GitHub Release tag without explicit user go-ahead.

---

## Order

1. **Restricted-license toggle** — smallest, no new training paths.
2. **GGUF export** — highest user value (real interop with `llama.cpp` / Ollama / LM Studio).
3. **CPU fallback (≤100M models)** — broadens reach to non-GPU hosts.
4. **HF Hub push** — written + unit-tested; smoke-test deferred until the user provides an HF token (private test repo).

Each commits independently. If anything snowballs in scope, stop and surface it.

---

## Task 1: Restricted-license toggle

**Why:** Llama 3 (Meta), Gemma (Google), DeepSeek-R1 are the highest-demand bases users ask for, but their licenses carry use-policy restrictions that the Apache/MIT-only allowlist correctly excludes. A user-toggleable opt-in lets people use them with eyes-open consent.

**Files:**
- `sidecar/llm_chain_sidecar/models/data/*.yaml` — extend the registry with a `restricted` license tier carrying `license_caveat` text.
- `sidecar/llm_chain_sidecar/models/registry.py` — `entries` accepts an `include_restricted: bool` flag; default `False` keeps current behavior.
- `sidecar/llm_chain_sidecar/api/routes.py` — `/api/models` accepts `?include_restricted=1`.
- `apps/desktop/src/screens/Settings.tsx` — new toggle "Allow restricted-license models (Llama, Gemma, DeepSeek)" persisted to `state/settings.ts`.
- `apps/desktop/src/screens/ModelPicker.tsx` — pass the flag to the API; show the `license_caveat` text inline on restricted entries with an amber warning chip.

**Tests:**
- `tests/models/test_registry.py` — new entries appear only when flag set.
- `tests/api/test_routes.py` — `/api/models` filters correctly with and without `?include_restricted=1`.
- `apps/desktop/src/api/__tests__/client.test.ts` — `getModels` forwards the flag.

**Acceptance:** With the toggle off, `getModels()` returns Apache/MIT only (current behavior). With it on, Llama-3-8B / Gemma-2-9B / DeepSeek-R1-Distill-Qwen-7B appear with caveat copy. Selecting one and starting a run still works (it's the same training path).

## Task 2: GGUF export

**Why:** The current adapter output is `safetensors` peft format. To load in `llama.cpp`, Ollama, LM Studio, etc., the user needs the merged model in GGUF format. This is the single highest-value post-training step.

**Approach:** Use `llama.cpp`'s `convert_hf_to_gguf.py` as a subprocess (it's the canonical converter and Apple Silicon-native). Bundle it via a small `scripts/llama-cpp-bootstrap.sh` that pip-installs `gguf` and clones the convert script into a known location, then call it from a new sidecar route. Ship the merge step (peft adapter + base → merged HF dir) before the convert step; both happen on demand from a button on RunDetail.

**Files:**
- `sidecar/llm_chain_sidecar/exports/__init__.py`, `gguf.py` — new module:
  - `merge_adapter(run_id) -> Path` (uses `peft.PeftModel.merge_and_unload()`).
  - `convert_to_gguf(merged_dir, quant: str = "q4_k_m") -> Path` (subprocess wrapper).
- `sidecar/llm_chain_sidecar/api/routes.py` — `POST /api/runs/{id}/export/gguf` returns immediately and streams progress on SSE; `GET /api/runs/{id}/export/gguf` returns the final path.
- `apps/desktop/src/screens/Runs.tsx` — "Export to GGUF" button on RunDetail visible when `status == "succeeded"`; shows quant-level dropdown (`q4_k_m`, `q8_0`, `f16`); progress and download-link surface inline.
- `scripts/llama-cpp-bootstrap.sh` — checked-in script that installs `gguf` and pulls the convert script. Documented in setup.md.
- `sidecar/pyproject.toml` — add `gguf>=0.9` to deps.

**Tests:**
- `tests/exports/test_merge.py` — uses `hf-internal-testing/tiny-random-LlamaForCausalLM` + a fake adapter dir to verify `merge_adapter` writes a sane HF model dir.
- `tests/exports/test_gguf.py` — patches the `convert_hf_to_gguf.py` subprocess and verifies the output path contract; gated by `pytest.mark.slow` if it's expensive.
- `tests/api/test_routes.py` — `POST /api/runs/{id}/export/gguf` returns 404 for non-existent / non-succeeded runs and 202 for valid ones.

**Acceptance:** End-to-end smoke: train a tiny model on the existing tiny-chat dataset, click Export, get a `.gguf` on disk that `llama-cli` can load.

## Task 3: CPU fallback (≤100M models)

**Why:** Today the Dashboard renders CPU as "non-selectable" for non-GPU hosts; the app effectively refuses to run. A pure-CPU path lets users on a stock laptop train tiny models — slowly — which is also useful for CI smoke and demos.

**Approach:** Add a `CpuTrainer` that mirrors `HfCudaTrainer` but uses `torch.device("cpu")` and refuses models above a hard cap (100M params, configurable by the capability gate). Update the Dashboard so a CPU device with `capabilities.cpu_max_params > 0` becomes selectable.

**Files:**
- `sidecar/llm_chain_sidecar/hardware/capabilities.py` — return a non-zero `cpu_max_params: int` for CPU devices (100M).
- `sidecar/llm_chain_sidecar/trainers/cpu.py` — new `CpuTrainer` (very small; mostly the HF path with `.to("cpu")` and no bnb/QLoRA).
- `sidecar/llm_chain_sidecar/trainers/__init__.py` — `make_trainer("cpu", ...)`.
- `apps/desktop/src/screens/Dashboard.tsx` — CPU is selectable when `capabilities.cpu_max_params > 0`.
- `apps/desktop/src/screens/ModelPicker.tsx` — gate uses `cpu_max_params` when device.backend == "cpu".

**Tests:**
- `tests/hardware/test_capabilities.py` — CPU returns the new cap.
- `tests/trainers/test_cpu.py` — mirrors `test_hf_cuda` shape (mocks `_run_training_loop`).
- The existing `test_real_lora_step_on_cuda` slow test gets a CPU sibling that's not gated by hardware; it can run in default CI as a real smoke test (just very slow).

**Acceptance:** Launching the app on a Mac with no GPU no longer leaves the user stuck. Picking CPU + a 100M model + the tiny-chat dataset trains end-to-end (slowly) and produces an adapter.

## Task 4: HF Hub push

**Why:** Users who want to publish their adapter shouldn't have to drop into a terminal. A button next to "Reveal in Finder" closes the loop.

**Approach:** Use `huggingface_hub.upload_folder()`. Token comes from `~/.cache/huggingface/token` (the standard HF auth file) so we don't store secrets ourselves; the UI surfaces "not signed in — run `huggingface-cli login` in a terminal" if no token is present.

**Files:**
- `sidecar/llm_chain_sidecar/exports/hub.py` — `push_to_hub(run_id, repo_id, private: bool) -> str` that returns the repo URL.
- `sidecar/llm_chain_sidecar/api/routes.py` — `POST /api/runs/{id}/export/hub`.
- `apps/desktop/src/screens/Runs.tsx` — "Push to Hugging Face Hub" button + repo-id input + private toggle on RunDetail (visible on succeeded runs).
- `sidecar/pyproject.toml` — `huggingface_hub` is already pulled by transformers; just confirm the version is recent enough.

**Tests:**
- `tests/exports/test_hub.py` — patches `upload_folder`, verifies (a) we surface a clear error when no token is present, (b) `repo_id` and `private` are forwarded correctly.
- `tests/api/test_routes.py` — endpoint contract.

**Acceptance:** End-to-end smoke deferred — needs the user to run `huggingface-cli login` and provide a test repo. Code merges in passing unit tests; user enables the feature when ready.
